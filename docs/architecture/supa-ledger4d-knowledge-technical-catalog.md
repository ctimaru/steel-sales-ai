## Safe repeatable audit

[`supabase/audits/supa_ledger4d_knowledge_technical_readonly.sql`](../../supabase/audits/supa_ledger4d_knowledge_technical_readonly.sql) is a single SELECT-based probe of schema, function grants, source integrity and bounded coverage. It is outside `supabase/migrations` intentionally.

**Executed against production: 22/22 checks passed** on 21 October 2026. These checks prove the listed metadata/data-invariant conditions only; they cannot prove a clean schema rebuild is equivalent to the applied migration ledger.

Other point-in-time counts: **19** standards; 977 geometries; 147 dimensional rows; 173 weights (**132 published with source**, **41 calculated**, **109 canonical published**, **0 canonical calculated**); 179 applicability rows (**0** marked normative-complete); 4 EN 10217 supplier range envelopes (all incomplete and source-backed); 81 reference observations; 52 golden cases/260 non-orphaned target chunks. Where 132 published are classified, none has a missing source or nonpositive weight. The distinction between published, theoretical/calculated and normative-complete is essential for credibility in School, calculators, RFQ and future AI.

### Product/technical implications

- **Trust boundary:** a manufacturer's published catalog measurement is *not* the same as a dimension wholly defined or available under EN 10210/10219/10216/10217. Keep provenance, `weight_method`, `knowledge_source_id` and `combination_complete` visible to the eventual AI response and UI.
- **Golden retrieval:** allow `service_role` testing only; public users should not receive the internal golden query dataset. No dangling targets currently, but clean-build insertion behavior still differs.
- **Historical replay:** never run either structural-seed version or reference-index migration on production as a 'repair'. A ledger history fix needs official reviewed procedure plus reproducible rebuild and an impact diff.
- **Follow-up:** isolate the structurally different SK4.2 seed and M5 golden-target insert for **fixture-based clean rebuild** comparisons once test infrastructure is appropriate; these are not production incidents proven by the catalog audit.
- **Remaining global #780 work:** two private price-list SQL-token divergences remain for **SUPA-LEDGER4E**. Migration version drift, duplicated names, 12 local-only / 36 remote-only and the official linked CLI PostgreSQL password failure remain unresolved. **#780 stays OPEN**, and IDENTITY2D #799/#801/#803 remain held from release.
- **Railway is deferred by user**; do not reset the DB password or touch production migrations to complete this audit.

**Exit criterion:** SQL-only repeatable read-only audit, documented seven historical divergences with current-catalog interpretation, GitHub checks green before review/merge, no production write.
